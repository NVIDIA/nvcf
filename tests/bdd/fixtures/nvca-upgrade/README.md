# NVCA upgrade regression lab

This CPU-only lab runs the production ICMS application, Cassandra, NATS, the
NVCA operator, and the real admission webhook. A probe substitutes for the NVCA
agent. It registers on startup and exposes the health endpoints the operator
expects. Its synthetic device has zero capacity. This test does not validate
GPU discovery or workload execution.

The fixture also supplies ephemeral signed JWTs and adapts the NGC cluster
route to the real ICMS account route. Cluster creation, updates, registration,
heartbeats, and persistence all execute in ICMS. The route adapter leaves the
backend's `nvcaVersion` unchanged. No external account credentials are needed.

## Prepare a dedicated lab

Run from the repository root with Docker, k3d, kubectl, Helm, Go, curl, and
Bazel installed. See the root `BAZEL.md` for the Java toolchain setup.

```sh
export NVCA_BDD_CLUSTER=nvca-upgrade-bdd-example
export NVCA_BDD_OUT="$(mktemp -d /tmp/nvca-upgrade-bdd.XXXXXX)"
export NVCA_BDD_PORT=18107

bazel build //src/control-plane-services/instance-cluster-management/icms-service:app

(
  cd src/compute-plane-services/nvca
  dra_version="$(GOWORK=off go list -mod=vendor -m -f '{{.Version}}' github.com/NVIDIA/k8s-dra-driver-gpu)"
  CGO_ENABLED=0 GOWORK=off go build -mod=vendor \
    -ldflags "-X github.com/NVIDIA/k8s-dra-driver-gpu/internal/info.version=${dra_version%%+*}" \
    -o "$NVCA_BDD_OUT/nvca-operator" ./cmd/nvca-operator
  CGO_ENABLED=0 GOWORK=off go build -mod=vendor \
    -ldflags "-X github.com/NVIDIA/k8s-dra-driver-gpu/internal/info.version=${dra_version%%+*}" \
    -o "$NVCA_BDD_OUT/webhook-server" ./cmd/webhook-server
)

k3d cluster create "$NVCA_BDD_CLUSTER" --servers 1 --agents 0 --no-lb \
  --api-port 127.0.0.1:16492 \
  --kubeconfig-update-default=false --kubeconfig-switch-context=false
k3d kubeconfig get "$NVCA_BDD_CLUSTER" > "$NVCA_BDD_OUT/kubeconfig"
chmod 600 "$NVCA_BDD_OUT/kubeconfig"

bash tests/bdd/fixtures/nvca-upgrade/prepare-lab.sh \
  "$NVCA_BDD_CLUSTER" "$NVCA_BDD_OUT/kubeconfig" "$NVCA_BDD_OUT" \
  bazel-bin/src/control-plane-services/instance-cluster-management/icms-service/app.jar \
  "$NVCA_BDD_OUT/nvca-operator" "$NVCA_BDD_OUT/webhook-server"
```

The helper accepts only a fresh lab namespace. The reused ICMS development
schema resets the `test` keyspace, so the helper refuses an existing namespace
before applying any schema. It leaves the cluster, images, logs, and kubeconfig
for inspection. The live wrapper owns the loopback port-forward for its run.

`NVCA_BDD_VERSION_A` and `NVCA_BDD_VERSION_B` select two different synthetic
probe versions. Their defaults are `0.0.1` and `0.0.2`. These are test image
identities, not released NVCA pins. The feature reads the expected versions
from the environment generated by the helper.

## Run the feature

```sh
bash tests/bdd/fixtures/nvca-upgrade/run-live.sh "$NVCA_BDD_OUT/environment.sh"
```

The wrapper runs `go test -run '^TestNVCAUpgrade$' -count=1 -timeout=20m -v`
from `tests/bdd/` and stops its port-forward on completion or failure.
Run the whole feature against a fresh lab. Its scenarios share the cluster
created by the first scenario. It covers:

- A startup registration reaching real ICMS through the lab identity provider.
- A pending upgrade surviving a completed old-agent registration and heartbeat.
- An explicit downgrade surviving a newer-agent registration.
- Operator reconciliation updating the backend version and agent image.
- Helm-managed registration continuing to report the running version.

The operator is stopped before configuration changes to make the registration
ordering deterministic. A bounded scenario teardown restores it after a failed
assertion or cancellation. Exact database read/write interleavings and legacy
version initialization remain covered by the Java/Cassandra regression tests.

For a negative control, prepare a second fresh lab with a different cluster
name, API port, output directory, and `NVCA_BDD_PORT`. Pass an unfixed ICMS jar
to the same helper and run this feature from the test checkout. The upgrade
scenario must fail when the old-agent registration changes `nvcaVersion` back
to the running version. The same feature must pass with the fixed jar.

The non-live wiring tests use canned observations. They validate step
registration and restoration behavior; they do not validate an ICMS deployment.
