# Figures

The architecture figures in nvstor's documents. Each one is an SVG
generated by a Python script, with a light and a dark PNG rendered beside
it. Documents embed the SVG.

| Figure | Script | Used in |
|---|---|---|
| `nvstor-system-context.svg` | `scripts/nvstor-system-context.py` | `docs/ARCHITECTURE.md` §1, `README.md` |
| `nvstor-write-durability.svg` | `scripts/nvstor-write-durability.py` | `docs/ARCHITECTURE.md` §4 |
| `nvstor-nfs-rdma-data-path.svg` | `scripts/nvstor-nfs-rdma-data-path.py` | `docs/ARCHITECTURE.md` §5.2, `docs/nfs-rdma.md` |
| `nvstor-s3-rdma-v2.svg` | `scripts/nvstor-s3-rdma-v2.py` | `docs/ARCHITECTURE.md` §6.2 |
| `nvstor-peer-fanout.svg` | `scripts/nvstor-peer-fanout.py` | `docs/ARCHITECTURE.md` §8, `docs/peer-copy.md` |
| `nvstor-gpu-rails.svg` | `scripts/nvstor-gpu-rails.py` | `docs/ARCHITECTURE.md` §11.2, `deploy/nfs-rdma/README.md` |

## Style

`scripts/figlib.py` holds the drawing rules, so each figure script only
places components and paths: white canvas, 1 pt black primary paths and
dashed grey optional or fallback paths, numbered callouts on straight
segments, groups only around several components, one icon size (48), and
colour only by category.

The icons are simple vector drawings defined in `figlib.py`
(`ICON_GLYPHS`): a coloured disc for the category with a glyph on it. Each
SVG carries the icons it uses as `<symbol>` elements, so it renders on any
code host or browser without loading external files and holds no raster
images.

| Colour | Category | Icons | Used for |
|---|---|---|---|
| Green | nvstor service | cube | nvstor's own services and modules; a green group outline is an nvstor process or pod |
| Red | Third-party software | plug | The Linux kernel NFS and NBD clients, `aws` and S3 SDKs |
| Blue | Actor | monitor, person | A client host or program (fast-path clients, `nvstor-client`) |
| Orange | Data | document, cylinder | PmStore, ChunkManager, MetadataStore, manifests |
| Purple | Resource | server, window, chip, shield, folder | Nodes, workloads, NICs and registered memory, authentication boundaries, directories |
| Yellow | Function | funnel, prompt | Admission control, dispatchers and worker threads |

Sequence diagrams and the crate graph are Mermaid inside the documents.

## Regenerate

Needs Python 3 and Node with Playwright and its Chromium. Playwright can be
installed without root anywhere, for example:

```sh
mkdir -p ~/.cache/nvstor-figures && cd ~/.cache/nvstor-figures
npm init -y && npm install playwright@1.47.2 && npx playwright install chromium
```

Then, from the repository root:

```sh
NODE_PATH=~/.cache/nvstor-figures/node_modules docs/figures/scripts/render.sh            # every figure
NODE_PATH=~/.cache/nvstor-figures/node_modules docs/figures/scripts/render.sh nvstor-gpu-rails
```

For each figure `render.sh` runs the figure script, which writes the SVG
and checks that it parses as XML, and then `scripts/render.cjs`, which:

- rejects scripts, `foreignObject`, event handlers, DOCTYPE or entity
  declarations, CSS imports, embedded raster images and any reference that
  is not to an element of the same document;
- renders the SVG in Chromium with JavaScript disabled and every network
  request blocked, and fails if any text leaves the view box or the card
  named by its `data-fit` attribute;
- writes `<figure>-light.png` (the figure on white) and `<figure>-dark.png`
  (the same figure on a dark surround, as in a dark-themed viewer) at 2×.

Look at both PNGs before committing, and update the SVG and PNGs together.

When a figure's subject changes in code, change the script, not the SVG: the
docstring at the top of each script names the source files it was drawn
from.
