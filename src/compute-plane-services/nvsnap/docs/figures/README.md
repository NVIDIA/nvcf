## Style

The figures follow the NVIDIA Cloud Architecture Diagrams Style Guide v1.1
as the `nvaf-architecture-diagrams` skill applies it
(`.agents/skills/nvaf-architecture-diagrams/SKILL.md` and its
`references/nvidia-cloud-architecture-style.md`, copied unchanged from the
nvaf repository, as flashbox and bedrock do): white canvas, 1 pt black
primary paths and dashed #999999 optional paths, numbered callouts on
straight segments, groups only around several components, one icon size
(48), colors only by category. `scripts/figlib.py` holds those rules, so each
figure script only places components and paths. The canvas is white in
both themes: on a dark page the figure shows as a white panel, as the guide
requires.

What the colors mean here:

| Color (icon) | Category | Used for |
|---|---|---|
| Green | NVIDIA service | nvsnap's agent, webhook and server; a green outline is an nvsnap component |
| Red | Third-party service | The Kubernetes API, CRIU, an object-store bucket |
| Blue | Actor | NVCA or another controller that creates pods |
| Orange | Data | Checkpoints, chunk stores, volumes, the catalog, group records |
| Purple | Resource | Pods, node disks, directories, checks |
| Yellow | Function | Admission (the webhook's mutation), the download Job |

## Regenerate

Needs Python 3 and Node with Playwright (the renderer drives a locked-down
Chromium: no scripts, no network, one SVG root). Playwright installs without
root anywhere, for example:

```sh
mkdir -p ~/.cache/nvsnap-figures && cd ~/.cache/nvsnap-figures
npm init -y && npm install playwright@1.47.2 && npx playwright install chromium
```

Then, from the nvsnap directory:

```sh
NODE_PATH=~/.cache/nvsnap-figures/node_modules docs/figures/scripts/render.sh                 # every figure
NODE_PATH=~/.cache/nvsnap-figures/node_modules docs/figures/scripts/render.sh nvsnap-data-tiers
```

`render.sh` runs the figure script (which writes the SVG and checks that it
parses as XML) and then
`.agents/skills/nvaf-architecture-diagrams/scripts/render-and-check.cjs`,
which rejects unsafe SVG content, fails if any text leaves the view box or
its card (`data-fit`), and writes `<figure>-light.png` and
`<figure>-dark.png` at 2×. Look at both PNGs before committing, and commit
the script, the SVG and the PNGs together.

`make check-docs` and the `nvsnap docs` workflow run `scripts/check.py`,
which redraws every SVG from its script and fails when one differs from the
committed SVG, when a PNG is missing, or when a file here has no script.

When a figure's subject changes in code, change the script, not the SVG:
the docstring at the top of each script names the source files it was drawn
from.

## Icons

`assets/nvsnap/` holds unmodified 192 × 192 PNG components from the NVIDIA
Cloud Architecture Diagrams Style Guide v1.1, copied byte for byte from the
icon sets already in use in flashbox (`docs/figures/assets/flashbox-federation/`)
and nvaf (`docs/figures/assets/nvaf-turn-orchestration/`). Figures scale them
uniformly and never recolor, crop, flip or rotate them. Each SVG embeds the
icons it uses as data-URI symbols with a `data-source` attribute naming the
file, so GitHub renders it without loading anything external.
