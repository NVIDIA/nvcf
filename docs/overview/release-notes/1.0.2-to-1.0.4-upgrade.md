# Upgrade from docs edition 1.0.2 to NVCF 1.0.4

<Warning>
Candidate procedure, pending QA. This preview does not qualify the selected
combination or authorize customer publication. Use the exact candidate bundle
and record any environment or registry overrides with the QA results.
</Warning>

The comparison starts from docs edition 1.0.2. Its stack selection also appears
in the docs-only 1.0.3 edition. Stack versions are independent of the NVCF
umbrella version.

| Stack | Docs edition 1.0.2 | NVCF 1.0.4 candidate |
| --- | --- | --- |
| Self-Managed | 1.0.1 | 1.0.7 |
| Compute Plane | 1.0.0 | 1.0.4 |
| Observability | 1.0.0 | 1.0.0 |

See the [artifact manifest](../manifest.md) for selected chart and image
versions and the [candidate release notes](../../../fern/changelog/2026-10-26.mdx)
for the customer-visible changes. Earlier QA using Self-Managed 1.0.2 and
Compute Plane 1.0.1 is a different selection, not this comparison baseline.

## Before starting

- Retain the source configuration, Helm values, image references, database
  backups and persistent-volume snapshots. Record cluster registrations,
  function and deployment IDs, running tasks, schema versions and receipt state.
- Verify the [candidate manifest and bundle identity](../manifest.md#candidate-identity).
  Preserve the bundle's sibling `deploy/stacks/` directories. Do not select
  incidental stack files from the umbrella branch or substitute latest releases.
- Use Helm 3.21.4 and Helmfile 1.1.9 from the candidate manifest. Helmfile must
  retain sequential deployment ordering. Prepare separate environment and
  secrets files and select each Kubernetes context explicitly.
- Configure [customer artifact access](../umbrella-releases.md#configure-customer-artifact-access)
  in both selected stack environments: authenticated HTTPS charts at
  `https://helm.ngc.nvidia.com/nvidia/nvcf`, image registry `nvcr.io` and image
  repository `nvidia/nvcf`. Replace the base placeholders and supply image and
  worker-sidecar credentials separately. These inputs preserve the selected
  versions; the HTTPS URL alone is insufficient without customer credentials.
- Check chart and image access from the deployment environment. Preserve the
  selected API chart 1.27.4, API runtime 1.18.1 and worker overrides. Compute
  Plane 1.0.4 supplies Samba 1.0.9 and both collector images
  0.160.0-nv-0.2.9 to operator chart 1.28.0. Customer access to Samba 1.0.9
  and BDD results for this revised selection remain pending verification.
- Keep a serving function, a secret-bearing workload and a running task as
  upgrade canaries. Capture invocation availability throughout the procedure.
  Check storage ownership, permissions and admission policy before rolling
  non-root workers. Samba still requires its existing root runtime.

For an older source stack, complete its
[staged upgrade to Self-Managed 1.0.1](0.6.1-to-1.0.1-upgrade.md) first.
Do not skip schema or data-backfill stops. ICMS's legacy instance lookup
backfill is opt-in: use `MIGRATE`, then `VALIDATE`, then `DISABLED` only when
that earlier migration requires it. Validation must report no active rows
with missing requests, mismatches or failures.

## Upgrade order

1. Refresh the existing gateway hostname policy with the target bundle before
   changing the admin issuer route. The normal apply orders that route before
   ingress, so it cannot repair the old policy soon enough on its own:

   ```bash
   make -C "$TARGET_BUNDLE/deploy/stacks/self-managed" apply-hostname-policy \
     HELMFILE_ENV="$HELMFILE_ENV" KUBECONFIG_FILE="$CONTROL_KUBECONFIG"
   ```

   The target checks that the selected gateway-routes chart contains the
   corrected policy. Stop if that check fails; do not disable admission.

2. Upgrade the existing NVCA installation using Compute Plane 1.0.4 before
   changing shared worker defaults. Keep the registered cluster identity and
   existing workloads. Verify that NVCA 3.10.3 is ready and that old-image
   function and task canaries still work.

3. Stop admitting new work long enough to drain pending work in single-replica
   memory queues before NATS or dependent service rollouts. The request-identity
   fix handles reused stream sequence numbers; it does not make memory queues
   durable. An already-empty stream may reset its sequence. Pending-message
   loss is a failure.

4. Apply Self-Managed 1.0.7 with the packaged Helmfile and the reviewed target
   configuration. Keep the environment, secrets and selected contexts explicit.
   Wait for migration jobs, services and the upgrade receipt to complete before
   resuming traffic. Retain Observability 1.0.0.

5. Verify original function/deployment IDs, cluster registration and persistent
   data. Exercise existing workloads and new function/task creation. For
   secret-bearing workloads, verify initial delivery and natural refresh,
   unchanged ownership and permissions, and successful invocation.

6. Repeat apply and confirm idempotency. Exercise worker replacement through the
   instance-termination API, then verify task completion, state and invocation
   continuity. New worker defaults take effect when workers are replaced;
   changing the defaults alone does not replace every existing worker.

Use the bundle's README and per-stack Makefile/Helmfile entry points for the
actual apply commands. Reuse the existing registration values for an upgrade;
do not run fresh cluster registration over the existing identity.

## Checks for changed behavior

| Area | Check after upgrade |
| --- | --- |
| API | LLM requests sent to the unsupported classic invocation endpoint return the existing not-found response promptly. Supported classic requests and access checks still work. |
| NVCA and NATS | A new deployment or termination request is processed even if a restarted stream reuses an old transport sequence. Genuine redelivery remains idempotent. |
| NATS authentication | Authentication recovers after reconnect, and an NKey plugin does not change the account used by a subsequent plugin. The callout's `/readyz` reflects connection readiness; `/healthz` remains live while reconnecting. |
| ESS agent | A non-root secret refresh preserves an existing readable file's owner and mode with the required `CHOWN` capability. The earlier readable 0644 test does not establish arbitrary restrictive-permission or persistent-volume support. |
| ICMS | Instance events and reconnection preserve deployment state. Check legacy lookup fields if the installation previously required a backfill. |
| Pylon | Queued LLM requests may wait up to 300 seconds for first output after response headers. The 30-second inter-token stall deadline remains. |
| Samba storage | Verify a non-root Helm task can create its results directory and write to the share. Samba 1.0.9 applies share ownership and permissions before starting its daemon and fails startup when that setup fails. Its daemon still uses the existing root runtime. |
| Workers and telemetry | Check NICLLS when enabled, Samba-backed storage, and both ordinary and BYOO collector paths that the deployment uses. |

NATS now defaults to upstream `docker.io/synadia/nats-server:2.14.6-alpine3.22`
with UID/GID 1000. The stack accepts server, reloader and box image overrides.
cert-manager and Vault injector overrides are also available, but do not change
their defaults automatically. Keep cert-manager components and CRDs compatible,
keep OpenBao server/agent selections paired, and record exact overrides.

## Rollback boundary

The procedure under QA restores prior control-plane and default worker
selections while retaining patched NVCA and corrected invocation probes.
Verify original identities, old-image canaries, durable data and availability
after rollback. It does not establish an old-agent downgrade or database
migration reversal. Restore durable data only through the reviewed recovery
procedure for that datastore. Changing the docs selector does not roll back a
running deployment.

Cassandra runtime remains 5.0.9-nv-2.0.5 and OpenBao server/agent remain
2.6.2-nv-1.3.4. Their migration images advance to 0.17.7 and 0.19.9 respectively.
Large runtime upgrades, state-metrics changes and a Samba non-root redesign
are outside this candidate.
